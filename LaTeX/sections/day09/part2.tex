    \node[b, draw=treegreen]   (e) at (8.8,0) {Statistics\\and report};
    \foreach \a/\b in {a/b, b/c, c/d, d/e} { \draw[->] (\a) -- (\b); }
    \node[below, align=center] at (0,-0.55)   {one time,\\measured alone};
    \node[below, align=center] at (2.2,-0.55) {one time,\\measured alone};
    \node[below, align=center] at (4.4,-0.55) {not\\measured};
    \node[below, align=center] at (6.6,-0.55) {one time\\for each run};
    \node[below, align=center] at (8.8,-0.55) {median, p95,\\the method};
  \end{tikzpicture}\par\endgroup
  \vskip 0.4em
  \small
  \begin{itemize}
    \item One fixed input, ready before the clock starts.
    \item The clock is around one inference. Nothing else is in the window:
          no print, no file, no copy that the product does not need.
    \item Keep each time. Calculate the statistics after the loop.
    \item Read the temperature between the runs, not in a run.
    \item This is the loop of the sketch and of the script of the lab.
  \end{itemize}
  \keypoint{Each number of a report needs four facts: the warm-up runs, the
    timed runs, the input, and the statistic.}
\end{frame}

\begin{frame}{A percentile needs many runs}
  \begin{columns}[c]
    \begin{column}{0.46\textwidth}
      \footnotesize
      \renewcommand{\arraystretch}{1.2}
      \setlength{\tabcolsep}{4pt}
      \begin{tabular}{@{}rrr@{}}
        \toprule
        \textbf{Runs} & \textbf{Lowest p99} & \textbf{Highest p99} \\
        \midrule
        20   & 11.44 ms & 32.10 ms \\
        50   & 26.50 ms & 32.10 ms \\
        200  & 27.03 ms & 31.27 ms \\
        \bottomrule
      \end{tabular}
    \end{column}
    \begin{column}{0.52\textwidth}
      \small
      \begin{itemize}
        \item The same data as before: 3 percent of the inferences are
              slow.
        \item A group of 20 runs can have no slow inference. Its p99 is
              then 11.44 ms.
      \end{itemize}
    \end{column}
  \end{columns}
  \vskip 0.5em
  \small
  \begin{itemize}
    \item The rule of the rank: the p99 of $N$ runs is the value with the
          rank $0.99 \times N$, rounded up. For 20 runs, this is the
          maximum.
    \item To see an event that occurs one time in 100 runs, you need many
          times 100 runs.
    \item MLPerf Inference uses 24\,576 queries for a 90th percentile, and
          270\,336 queries for a 99th percentile.
  \end{itemize}
  \keypoint{With 20 runs, report the median and the maximum. Do not call
    the maximum a p99.}
  \source{An experiment of this course on an x86 processor.\\
    Query numbers: the rules of MLPerf Inference.}
\end{frame}

\begin{frame}{The clock}
  \footnotesize
  \renewcommand{\arraystretch}{1.2}
  \begin{tabular}{@{}L{0.33\textwidth}L{0.17\textwidth}L{0.40\textwidth}@{}}
    \toprule
    \textbf{Clock} & \textbf{Use it?} & \textbf{Reason} \\
    \midrule
    \code{time.perf\_counter\_ns()}
        & Yes, in Python
        & It does not go back, and it has a small step \\
    \code{time.time()}
        & No
        & It is the clock of the day. The system can set it during your
          run. \\
    \code{micros()}
        & Yes, in a sketch
        & A step of microseconds \\
    \code{millis()}
        & No
        & A step of 1 ms: an inference of 3.4 ms shows 3 or 4 \\
    \bottomrule
  \end{tabular}
  \vskip 0.4em
  \small
  \begin{itemize}
    \item A clock read has a cost. On the work computer, one read of
          \code{perf\_counter\_ns()} needs 146 ns.
    \item The window must be much longer than the step and the cost of the
          clock. For a window of some microseconds, time 1000 runs with one
          pair of clock reads.
    \item On a microcontroller you can also set a pin before and after the
          inference, and measure the pulse with an oscilloscope.
  \end{itemize}
  \source{The cost of a clock read: an experiment of this course.}
\end{frame}

% ------------------------------------------------------------------- window
\begin{frame}[fragile]{Model-only time and full pipeline time}
\begin{lstlisting}[style=python]
t0 = time.perf_counter_ns()
frame = camera.capture_array()                # capture
x = preprocess(frame)                         # resize, normalize
t1 = time.perf_counter_ns()
interpreter.set_tensor(input_index, x)
interpreter.invoke()                          # the model
y = interpreter.get_tensor(output_index)
t2 = time.perf_counter_ns()
boxes = postprocess(y)                        # decode, suppress
t3 = time.perf_counter_ns()
model_ms.append((t2 - t1) / 1e6)
pipeline_ms.append((t3 - t0) / 1e6)
\end{lstlisting}
  \small
  \begin{itemize}
    \item Two windows in one loop. \code{model\_ms} compares runtimes,
          precisions, and thread counts. \code{pipeline\_ms} is the time
          that the user waits.
    \item The frame rate of a product is 1000 divided by the pipeline time,
          not by the model time.
    \item MLPerf Tiny reports the model only. The lab of Day 8 reported the
          pipeline. The lab of today reports the model.
  \end{itemize}
  \keypoint{Give each time the name of its window. A comparison of a model
    time with a pipeline time is not valid.}
\end{frame}

\begin{frame}[fragile]{The same loop on a microcontroller}
\begin{lstlisting}[style=cpp]
for (int i = 0; i < kTimedRuns; i++) {
  bench_input(bench, input);            // fill the input: not in the window
  const unsigned long start = micros();
  interpreter.Invoke();                 // the window: the model only
  times_us[i] = micros() - start;
}
sortTimes(times_us, kTimedRuns);        // statistics after the loop
Serial.printf("median %lu us\n", percentileUs(times_us, kTimedRuns, 50));
\end{lstlisting}
  \small
  \begin{itemize}
    \item No \code{Serial.print} in the window. On a serial line with
          115\,200 baud, a line of 40 characters needs 3.5 ms.
    \item Fill the input before each inference. The interpreter can use the
          memory of the input tensor again for a later tensor.
    \item The result also depends on the memory of the arena (internal RAM
          or PSRAM), on the clock of the processor, and on the radio. Write
          the three settings in the report.
  \end{itemize}
  \keypoint{The rules are the same on each device: warm up, repeat, keep
    each time, and print after the loop.}
  \source{The sketch \texttt{kit\_bench} of the lab.}
\end{frame}

% ----------------------------------------------------------------- protocol
\begin{frame}{The protocol: write it before you measure}
  \small
  \begin{enumerate}
    \item The question: which decision does the number support?
    \item The seven parts: task, dataset, model, metrics, harness, system,
          run rules.
    \item The window: the first call and the last call.
    \item The warm-up runs and the timed runs, with a time limit.
    \item The statistics: the median, one high percentile, and the first
          inference.
    \item The number of repetitions of the complete benchmark.
    \item Your prediction for each result, with a reason.
  \end{enumerate}
  \vskip 0.3em
  \begin{itemize}
    \item A protocol that you write after the measurement follows the
          result that you like.
    \item A change during the work is permitted. Write the change and its
          reason.
    \item Part A of the lab: 20 minutes for this protocol, with one table
          for the two boards.
  \end{itemize}
  \keypoint{A result is useful when a second person can repeat it. The
    protocol is the instruction for that person.}
\end{frame}
