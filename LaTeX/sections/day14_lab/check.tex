\begin{frame}{Check criterion}
  \small
  The instructor checks this at the end of the lab:
  \begin{itemize}
    \item \cmark\ The proposal meets the five capstone requirements of
          \code{Docs/capstone.md}, Section 2.
    \item \cmark\ Each requirement of the proposal has a number and a test.
    \item \cmark\ Each budget has a value and a source, and each guess is
          marked as an estimate.
    \item \cmark\ The review sheet says ``approved'' or ``approved with
          changes'', and the proposal has the changes.
    \item \cmark\ \code{report.md} has the result of the first test and a
          plan for Day 15.
  \end{itemize}
  \vskip 0.4em
  \textbf{Hand in:} \code{proposal.md} and \code{report.md}.
\end{frame}

\begin{frame}{Decision Log}
  \begin{exerciseblock}
    How do you split the work between the XIAO and the Raspberry Pi in
    your system? Which budget numbers decided the split, and what did you
    give up?
  \end{exerciseblock}
  \vskip 0.2em
  A good Decision Log (about 100 words):
  \begin{itemize}
    \item gives the budget numbers that decided: for example the latency
          of the main path against its requirement, or the RAM of a model
          against the RAM of the board,
    \item says which numbers are estimates and when you measure them,
    \item names what you give up: for example the battery for a cable, or
          a larger model for a local decision.
  \end{itemize}
\end{frame}
