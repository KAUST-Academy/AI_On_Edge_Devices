    \textbf{MobileNetV2} & \textbf{Size of the graph} \\
    \midrule

    \bottomrule
  \end{tabular}

  \begin{itemize}

    \item All these graphs give the same class for an image. Their outputs

    \item The optimizer removes work. It does not remove information.
  \end{itemize}
  \keypoint{An optimizer changes the graph before the first inference.
    After that, each inference does less work.}

\begin{frame}{Six jobs of a graph optimizer}
  \small
  \renewcommand{\arraystretch}{1.2}
  \begin{tabular}{@{}L{0.24\textwidth}L{0.48\textwidth}L{0.19\textwidth}@{}}
    \toprule
    \textbf{Job} & \textbf{What it does} & \textbf{The result} \\
    \midrule
    Constant folding & It calculates each value that never changes, one
                       time & The same \\
    Removal of unused nodes & It removes each node that no output needs
                     & The same \\
    Operator fusion  & It makes one operator from operators in a row
                     & The same \\
    Memory layout    & It puts the values of a tensor in the order that
                       the kernels want & The same \\
    Shape planning   & It calculates the size of each tensor and plans the
                       memory & The same \\
    Precision selection & It changes \code{float32} to \code{float16} or
                       to \code{int8} & It changes \\
    \bottomrule
  \end{tabular}
  \vskip 0.5em
  \begin{itemize}
    \item ``The same'' means: the same to about 6 digits. The order of the
          additions changes, so the rounding changes.
    \item Only the last job needs data: a calibration set, and a test of
          the accuracy.
  \end{itemize}
\end{frame}

\begin{frame}{Removal of unused nodes}
  \small
  \renewcommand{\arraystretch}{1.25}
  \begin{tabular}{@{}L{0.30\textwidth}L{0.62\textwidth}@{}}
    \toprule
    \textbf{Node} & \textbf{Why it can go} \\
    \midrule
    Dropout  & In an inference, it gives its input as its output. \\
    Identity & It only copies a tensor. \\
    A node for the training & The loss, or a second output that only the
                               training reads. No output of the deployed
                               model needs it. \\
    Two equal subgraphs & They have the same inputs and the same
                          operators. One of them is enough. \\
    \bottomrule
  \end{tabular}
  \vskip 0.5em
  \begin{itemize}
    \item The optimizer starts at the outputs and goes back through the
          graph. A node that it does not reach has no reader.
    \item Put the model in the mode \code{eval()} before the export. A
          model in the training mode keeps its dropout, and its batch
          normalizations use the statistics of the batch.
  \end{itemize}
  \keypoint{A node that no output needs costs time at each inference.
    After the export, check that the file has only the nodes of the
    inference.}
\end{frame}

  \vskip 0.4em
  \small
  \begin{itemize}
    \item Each operator reads its input from the memory and writes its
          output to the memory. Three operators make three passes.
    \item The batch normalization and the ReLU do very little arithmetic
          for each byte. They are memory-bound (Part 1).
    \item The fused operator makes one pass. The values between the steps
          stay in a register.
    \item The first layer of MobileNetV2 in \code{float32}: the three
          operators move 8.2 MB. The fused operator moves 2.1 MB.
  \end{itemize}
  \keypoint{Fusion removes complete passes over the memory. It is the most
    important optimization for memory-bound operators.}
  \source{A calculation: an input of $224 \times 224 \times 3$ and a
    feature map of $112 \times 112 \times 32$, each tensor one time.}
\end{frame}

\begin{frame}{Fold the batch normalization into the convolution}
  \begin{columns}[c]
    \begin{column}{0.46\textwidth}
      In an inference, the two operators are:
      \[
        z = W * x + b
      \]
      \[
        y = \gamma \, \frac{z - \mu}{\sqrt{\sigma^2 + \varepsilon}} + \beta
      \]
    \end{column}
    \begin{column}{0.50\textwidth}
      One convolution gives the same $y$:
      \[
        s = \frac{\gamma}{\sqrt{\sigma^2 + \varepsilon}}
      \]
      \[
        W' = s\,W \qquad b' = s\,(b - \mu) + \beta
      \]
    \end{column}
  \end{columns}
  \vskip 0.4em
  \small
  \begin{itemize}
    \item $\gamma$ and $\beta$ are trained. $\mu$ and $\sigma^2$ are the
          mean and the variance that the training collected. After the
          training, all four are constants.
    \item Each output channel has its own $s$.
    \item The check on the first layer of MobileNetV2: the largest
          difference between the two outputs is $9.5 \times 10^{-7}$. The
          largest output is 3.1.
    \item The model loses 68\,224 values of its batch normalizations and
          gets 17\,056 bias values.
  \end{itemize}
  \keypoint{The folding is constant folding with algebra. After it, the
    batch normalization costs nothing.}
  \source{Formulas: \emph{Machine Learning Systems}, Volume I, chapter 13.
    Check and counts: an experiment of this course.}
\end{frame}

\begin{frame}{Fuse the activation}
  \begin{columns}[T]
    \begin{column}{0.48\textwidth}
      \begin{block}{How}
        \begin{itemize}
          \item ReLU is $\max(0, y)$. ReLU6 limits $y$ to the range from 0
                to 6.
          \item The kernel of the convolution applies the limit before it
                writes each output value.
          \item In \code{int8}, the limit is the limit of the integer
                range. It costs nothing.
        \end{itemize}
      \end{block}
    \end{column}
    \begin{column}{0.48\textwidth}
      \begin{block}{How you see it}
        \begin{itemize}
          \item LiteRT: the operator \code{CONV\_2D} has the property
                ``fused activation''.
          \item ONNX Runtime: the node \code{FusedConv}.
          \item NCNN: the convolution layer has the activation as a
                parameter.
        \end{itemize}
      \end{block}
    \end{column}
  \end{columns}
  \vskip 0.5em
  \small
  \begin{itemize}
    \item The LiteRT file of MobileNetV2 from the export of this course has
          no activation operator. All 35 are in the convolutions.
    \item A fusion is possible only when one operator reads the middle
          tensor. A tensor with two readers must exist in the memory.
    \item Some runtimes also fuse the addition of a residual connection
          into the convolution before it.
  \end{itemize}
\end{frame}

    \foreach \i/\c/\l in {0/cardinalred!45/R, 1/treegreen!45/G,
        2/skyblue!50/B, 3/cardinalred!45/R, 4/treegreen!45/G,
        5/skyblue!50/B, 6/cardinalred!45/R, 7/treegreen!45/G,
        8/skyblue!50/B, 9/cardinalred!45/R, 10/treegreen!45/G,
        11/skyblue!50/B} {
      \draw[coolgray, fill=\c] (\i,-1.5) rectangle (\i+1,-0.5);
      \node at (\i+0.5,-1.0) {\l};
    }
    \node[anchor=west] at (12.3,-1.0) {pixel by pixel};
  \end{tikzpicture}\par\endgroup
  \vskip 0.4em
  \small
  \begin{itemize}
    \item The figure shows an image of $2 \times 2$ pixels with 3 channels
          in the memory. The same 12 values, in two orders.
    \item PyTorch and ONNX use NCHW. LiteRT and XNNPACK use NHWC. A SIMD
          kernel is fast when the values that it needs lie side by side.
    \item ONNX Runtime on x86 uses a third layout: blocks of 8 channels,
          which fill one AVX2 register. This is the last level of the
          table before.
    \item Where two layouts meet, the converter adds a \code{Transpose}
          operator. The LiteRT file from PyTorch has one at its input.
  \end{itemize}
  \keypoint{Check the input shape of each file in Netron: $1 \times 3
    \times 224 \times 224$ or $1 \times 224 \times 224 \times 3$. Your
    pre-processing must give this order.}
\end{frame}

% ------------------------------------------------------------------ shapes
\begin{frame}{Static shapes: the runtime plans one time}
  \begin{columns}[T]
    \begin{column}{0.48\textwidth}
      \begin{block}{With all shapes known}
        \begin{itemize}
          \item The size of each tensor is a constant.
          \item The runtime plans the memory before the first inference:
                one arena, as on Day 3.
          \item Two tensors that never live at the same time share the
                same bytes.
        \end{itemize}
      \end{block}
    \end{column}
    \begin{column}{0.48\textwidth}
      \begin{block}{What you gain}
        \begin{itemize}
          \item No memory allocation during an inference.
          \item A peak memory that you know before the deployment.
          \item A latency that changes little from run to run.
        \end{itemize}
      \end{block}
    \end{column}
  \end{columns}
  \vskip 0.5em
  \begin{itemize}
    \item In LiteRT, the call \code{allocate\_tensors()} does this plan.
          For MobileNetV2 it needs 10 ms, one time.
    \item Some backends accept only static shapes. An NPU is the usual
          example.
  \end{itemize}
  \source{Time of the plan: an experiment of this course on an x86
    processor.}
\end{frame}

\begin{frame}[fragile]{Dynamic shapes: one file, more input sizes}
\begin{lstlisting}[style=python]
batch = torch.export.Dim("batch", min=1, max=64)

torch.onnx.export(model, (example,), "mnv2_dynamic.onnx",
                  input_names=["image"], output_names=["logits"],
                  dynamic_shapes={"x": {0: batch}},
                  dynamo=True, external_data=False)
\end{lstlisting}
  \small
  \begin{itemize}
    \item A dimension of the input gets a name in place of a number. Netron
          shows the input shape \code{batch} $\times\ 3 \times 224 \times
          224$.
    \item The key \code{"x"} is the name of the input in the function
          \code{forward} of the model.
    \item The static file accepts only its shape. With 2 images, ONNX
          Runtime stops with \code{Got: 2 Expected: 1}.
    \item The usual dynamic dimensions: the batch size, the size of the
          image, the length of a text.
  \end{itemize}
  \keypoint{A dynamic dimension is a decision at the export. The runtime
    cannot add it later.}
\end{frame}

\begin{frame}[fragile]{Precision calibration with ONNX Runtime}
\begin{lstlisting}[style=python]
from onnxruntime.quantization import (CalibrationDataReader, QuantFormat,
                                      QuantType, quantize_static)

class Reader(CalibrationDataReader):
    def __init__(self, images):
        self.items = iter([{"image": x[None]} for x in images])
    def get_next(self):
        return next(self.items, None)

quantize_static("mnv2_prepared.onnx", "mnv2_int8.onnx", Reader(images),
                quant_format=QuantFormat.QDQ, per_channel=True,
                activation_type=QuantType.QUInt8, weight_type=QuantType.QInt8)
\end{lstlisting}
  \small
  \begin{itemize}
    \item The tool is a part of the Python package of ONNX Runtime. Its
          function \code{quant\_pre\_process} makes the prepared file.
    \item The reader gives the calibration images one by one, with the
          pre-processing of the model. The tool runs the model and records
          the range of each activation (Day 4).
    \item The result is an ONNX file with \code{QuantizeLinear} and
          \code{DequantizeLinear} nodes. The runtime fuses them into
          \code{int8} operators.
  \end{itemize}
\end{frame}

\begin{frame}{Check what the optimizer did}
  \begin{enumerate}
    \item \textbf{Look.} Open the file before and after in Netron. Find the
          operators that are gone and the operators that are new.
    \item \textbf{Count.} Write the number of operators of each type.
    \item \textbf{Compare.} Give the two files the same input. The outputs
          must agree to about 6 digits for \code{float32}.
    \item \textbf{Measure.} The latency, the load time, and for a new
          precision the accuracy.
  \end{enumerate}
  \vskip 0.4em
  \small
  \renewcommand{\arraystretch}{1.2}
  \begin{tabular}{@{}L{0.20\textwidth}L{0.72\textwidth}@{}}
    \toprule
    \textbf{Runtime} & \textbf{Where you see the optimized graph} \\
    \midrule
    LiteRT, NCNN & In the exported file: the converter did the work. \\
    ONNX Runtime & Set \code{options.optimized\_model\_filepath}. The
                   runtime then writes the graph that it runs. \\
    \bottomrule
  \end{tabular}
  \vskip 0.4em
  \keypoint{Do not trust a setting. Look at the graph that runs.}
\end{frame}

\exerciseframe{fuse three operators on paper}{%
  \small
  A convolution has one filter with three weights and a bias. Then come a
  batch normalization and a ReLU. Ignore $\varepsilon$.
  \vskip 0.2em
  {\footnotesize
  \renewcommand{\arraystretch}{1.15}
  \begin{tabular}{@{}L{0.30\textwidth}L{0.60\textwidth}@{}}
    \toprule
    Convolution & $W = (2,\ -1,\ 0.5)$ and $b = 1$ \\
    Batch normalization & $\gamma = 3$, $\beta = -1$, $\mu = 3$,
                          $\sigma = 2$ \\
    \bottomrule
  \end{tabular}}
  \begin{enumerate}
    \item Calculate $s$, the weights $W'$, and the bias $b'$ of the fused
          convolution.
    \item The input is $x = (2,\ 1,\ 4)$. Calculate the output with the
          three operators, and then with the fused operator.
    \item Do the same for $x = (0,\ 2,\ 2)$. Where is the ReLU in the fused
          operator?
    \item The input tensor has 0.57 MB and each later tensor has 1.53 MB.
          Each operator reads its input and writes its output. How many MB
          move with three operators, and with the fused operator?
  \end{enumerate}
}

\answerframe{fuse three operators on paper}{%
  \small
  \begin{enumerate}
    \item $s = \gamma / \sigma = 1.5$. So $W' = (3,\ -1.5,\ 0.75)$ and
          $b' = 1.5 \times (1 - 3) - 1 = -4$.
    \item Three operators: $z = 4 - 1 + 2 + 1 = 6$. Then
          $y = 3 \times (6 - 3) / 2 - 1 = 3.5$. The ReLU keeps 3.5.
          Fused: $6 - 1.5 + 3 - 4 = 3.5$.
    \item Three operators: $z = 0 - 2 + 1 + 1 = 0$. Then
          $y = 3 \times (0 - 3) / 2 - 1 = -5.5$. The ReLU gives 0.
          Fused: $0 - 3 + 1.5 - 4 = -5.5$, and the limit at the end of the
          kernel gives 0. The ReLU is one comparison before the kernel
          writes the value.
    \item Three operators: $(0.57 + 1.53) + (1.53 + 1.53) + (1.53 + 1.53)
          = 8.22$ MB. Fused: $0.57 + 1.53 = 2.10$ MB. The fusion removes 74
          percent of the bytes that move.
  \end{enumerate}
  \vskip 0.1em
  The fused operator has 4 values in place of 8. The result is the same
  for each input.
}
