  \end{itemize}

% ------------------------------------------------------- comparison with a SBC
\begin{frame}{A microcontroller is not a small Raspberry Pi}
  \small
  \renewcommand{\arraystretch}{1.3}
  \begin{tabular}{@{}L{0.14\textwidth}L{0.38\textwidth}L{0.38\textwidth}@{}}
    \toprule
    & \textbf{XIAO ESP32S3 (microcontroller)}
    & \textbf{Raspberry Pi 5 (single-board computer)} \\
    \midrule
    Software & One program, the firmware
             & Linux and many processes \\
    RAM      & 512 KB, and 8 MB of PSRAM & 8 GB \\
    Storage  & 8 MB of flash & microSD card \\
    Timing   & The program controls each microsecond
             & The operating system can pause a program \\
    Pins     & Direct access to GPIO, ADC, and buses
             & GPIO and buses through Linux. No ADC. \\
    Sleep    & Modes that use microamperes
             & No such mode in normal use \\
    \bottomrule
  \end{tabular}
  \vskip 0.8em
  \keypoint{Use a microcontroller when the timing of a sensor and the
    energy decide. Use a single-board computer when the model needs
    gigabytes of memory.}
  \source{Kit pages of \emph{Machine Learning Systems}.}
\end{frame}

% ----------------------------------------------------------------------- PSRAM
\begin{frame}{PSRAM: more memory, slower access}
  \begin{columns}[T]
    \begin{column}{0.52\textwidth}
      \begin{itemize}
        \item PSRAM is pseudo-static RAM: dynamic memory cells with a
              controller that refreshes them.
        \item It connects to the processor through a serial bus. An
              access needs more time than an access to the internal RAM.
        \item The program must ask for PSRAM. In Arduino, the function
              \code{ps\_malloc()} takes memory from it.
      \end{itemize}
    \end{column}
    \begin{column}{0.44\textwidth}
      \begin{block}{Use the PSRAM for}
        \begin{itemize}
          \item an image buffer of the camera
          \item a tensor arena that does not fit the internal RAM
        \end{itemize}
      \end{block}
      \begin{block}{Use the internal RAM for}
        \begin{itemize}
          \item data that the program reads often
          \item a model that must be fast
        \end{itemize}
      \end{block}
    \end{column}
  \end{columns}
  \vskip 0.5em
  \keypoint{The build option \code{Tools > PSRAM > OPI PSRAM} of Day 1
    makes the 8 MB available. With the option off, the program has only the
    internal RAM.}
\end{frame}

  \begin{itemize}
    \item The processor does one step at each clock cycle. A higher
          frequency gives more steps each second.

          from a timer, not from the speed of the program.
  \end{itemize}

    Systems.}
\end{frame}

% ------------------------------------------------------------------------ GPIO
\begin{frame}[fragile]{GPIO: general-purpose input and output}
  \begin{columns}[T]
    \begin{column}{0.47\textwidth}
      \small
      \begin{itemize}
        \item A GPIO pin has two states: 0 V (low) and 3.3 V (high).
        \item As an output, the program sets the state: an LED, a relay.
        \item As an input, the program reads the state: a button, a
              motion detector.
        \item An open input has no defined state. A pull-up resistor
              holds it at high.
        \item The pins of the XIAO accept 3.3 V. A signal of 5 V damages
              a pin.
      \end{itemize}
    \end{column}
    \begin{column}{0.50\textwidth}
\begin{lstlisting}[style=python]
from machine import Pin

# The LED of the XIAO is on GPIO21.
# It is on when the pin is low.
led = Pin(21, Pin.OUT)
led.value(0)      # LED on
led.value(1)      # LED off

# The boot button is on GPIO0.
# It connects the pin to 0 V.
button = Pin(0, Pin.IN, Pin.PULL_UP)
print(button.value())   # 0 = pressed
\end{lstlisting}
    \end{column}
  \end{columns}
  \vskip 0.3em
  \keypoint{Read the pin number and the active level in the board
    documentation. The LED of the XIAO has inverted logic.}
\end{frame}

% ------------------------------------------------------------------------- ADC
\begin{frame}{ADC: from a voltage to a number}
  \begin{columns}[c]
    \begin{column}{0.44\textwidth}
      \centering
      \begin{tikzpicture}[font=\scriptsize, x=0.44cm, y=0.36cm]
        \draw[->, coolgray] (0,0) -- (8.8,0) node[below left, text=black]
          {input voltage};
        \draw[->, coolgray] (0,0) -- (0,8.9);
        \node[rotate=90, anchor=south] at (-0.8,4.2) {output number};
        \draw[coolgray, dashed] (0,0) -- (8,8);
        \foreach \k in {0,...,7} {
          \draw[cardinalred, line width=1pt] (\k,\k) -- (\k+1,\k);
          \node[anchor=east, coolgray] at (-0.05,\k) {\k};
        }
        \foreach \k in {1,...,7} {
          \draw[cardinalred, line width=1pt] (\k,\k-1) -- (\k,\k);
        }
        \node[anchor=west] at (3.2,1.4) {3 bits: 8 levels};
      \end{tikzpicture}
    \end{column}
    \begin{column}{0.54\textwidth}
      \small
      \begin{itemize}
        \item An analog-to-digital converter (ADC) measures a voltage and
              gives an integer.
        \item With $n$ bits, the ADC has $2^n$ levels.
              \[ \text{step} = \frac{V_{\text{range}}}{2^n} \]
        \item The ADC of the ESP32-S3 has 12 bits: 4096 levels. For a
              range of 3.3 V, one step is 0.8 mV.
        \item A change that is smaller than one step is not visible.
      \end{itemize}
    \end{column}
  \end{columns}
  \vskip 0.4em
  \keypoint{The IMU and the microphone of the kit have their own ADC. They
    send numbers on a bus. The ADC of the XIAO is for analog sensors, for
    example a light sensor.}
\end{frame}

% ---------------------------------------------------------------- bus overview
\begin{frame}{Four serial buses}
  \small
  \renewcommand{\arraystretch}{1.3}
  \setlength{\tabcolsep}{4pt}
  \begin{tabular}{@{}L{0.10\textwidth}L{0.20\textwidth}L{0.20\textwidth}L{0.19\textwidth}L{0.20\textwidth}@{}}
    \toprule
    & \textbf{Signal wires} & \textbf{Devices} & \textbf{Speed}
    & \textbf{On the kit} \\
    \midrule
    UART & 2: transmit, receive & 2, point to point
         & Low: 115\,200 bit/s is typical & Serial port to the laptop \\
    I2C  & 2: data, clock & Many, each with an address
         & Low: 100 or 400 kbit/s & IMU, display \\
    SPI  & 4: clock, 2 data, select & Many, each with a select wire
         & High: megabits each second & microSD card \\
    I2S  & 2 or 3: clocks, data & 1 audio device
         & Fixed by the audio rate & Microphone \\
    \bottomrule
  \end{tabular}
  \vskip 0.8em
  \begin{itemize}
    \item ``Serial'' means that the bits go one after the other on one
          wire.
    \item More wires and a clock wire give more speed. Fewer wires use
          fewer pins.
  \end{itemize}
\end{frame}

% ------------------------------------------------------------------------ UART
\begin{frame}{UART: two wires and no clock}
  \begingroup\centering
  \begin{tikzpicture}[font=\scriptsize, x=0.82cm, y=0.8cm]
    % the letter A = 0x41 = 0100 0001, least significant bit first
    \draw[cardinalred, line width=1pt]

      -- (8,1) -- (9,1) -- (9,0) -- (10,0) -- (10,1) -- (12,1);
    \foreach \x in {1,...,11} { \draw[coolgray!60, dashed] (\x,-0.15) -- (\x,1.3); }
    \node at (0.5,1.5) {idle};
    \node at (1.5,1.5) {start};
    \foreach \x/\b in {2/1,3/0,4/0,5/0,6/0,7/0,8/1,9/0} {
      \node at (\x+0.5,1.5) {\b};
    }
    \node at (10.5,1.5) {stop};
    \node at (11.5,1.5) {idle};
    \draw[<->, coolgray] (2,-0.4) -- node[below, text=black]
      {8 data bits: the letter ``A'' (0x41), lowest bit first} (10,-0.4);
  \end{tikzpicture}\par\endgroup
  \vskip 0.4em
  \begin{itemize}
    \item One wire for each direction: TX of one device goes to RX of the
          other device.
    \item No clock wire. The two devices must use the same bit rate, the
          baud rate.
    \item One byte needs 10 bits on the wire. At 115\,200 baud the limit
          is 11\,520 bytes each second.
    \item The XIAO gives a serial port over USB. The MicroPython prompt
          and \code{print()} use this port.
  \end{itemize}
\end{frame}

\begin{frame}{I2C: two wires and many devices}
  \begingroup\centering

    \node[d] (t2) at (8.0,0) {Display\\address 0x3C};

    \draw[treegreen, line width=1pt] (-1.2,-1.9) -- (9.4,-1.9);
    \node[darkcyan, font=\scriptsize, anchor=south] at (2.2,-1.3)
      {SDA: data (GPIO5)};
    \node[treegreen, font=\scriptsize, anchor=north] at (2.2,-1.9)
      {SCL: clock (GPIO6)};
    \foreach \n in {c,t1,t2} {
      \draw[darkcyan]  ([xshift=-0.4cm]\n.south) -- ([xshift=-0.4cm]\n.south |- 0,-1.3);
      \fill[darkcyan]  ([xshift=-0.4cm]\n.south |- 0,-1.3) circle (1.6pt);
      \draw[treegreen] ([xshift=0.4cm]\n.south) -- ([xshift=0.4cm]\n.south |- 0,-1.9);
      \fill[treegreen] ([xshift=0.4cm]\n.south |- 0,-1.9) circle (1.6pt);
    }
  \end{tikzpicture}\par\endgroup
  \vskip 0.4em
  \begin{itemize}
    \item The controller makes the clock and starts each transfer.
    \item Each target device has an address of 7 bits. The controller
          sends the address first. Only that device answers.
    \item Resistors pull the two wires to 3.3 V. A device can only pull a
          wire to 0 V.
    \item Typical speeds: 100 kbit/s and 400 kbit/s. This is enough for an
          IMU. It is too slow for audio or images.
  \end{itemize}
\end{frame}

\begin{frame}[fragile]{I2C: read one register of the IMU}

  \vskip 0.2em
  {\scriptsize S = start, P = stop, A = acknowledge, N = no acknowledge.
   White: the controller sends. Green: the IMU sends.\par}
  \vskip 0.3em
  \begin{itemize}
    \item A sensor is a list of registers. Each register has a number and
          holds one byte.
    \item The register 0x0F of the IMU holds its identity. The value is
          0x6A for the LSM6DS3TR-C.
  \end{itemize}
\begin{lstlisting}[style=python]
from machine import I2C, Pin
i2c = I2C(0, sda=Pin(5), scl=Pin(6), freq=400000)
print([hex(a) for a in i2c.scan()])        # ['0x3c', '0x6a']
print(hex(i2c.readfrom_mem(0x6A, 0x0F, 1)[0]))   # 0x6a
\end{lstlisting}

    the expected output. Nobody measured it on the kit.}

\begin{frame}{SPI: four wires and more speed}
  \begin{columns}[c]
    \begin{column}{0.50\textwidth}
      \centering
      \begin{tikzpicture}[font=\footnotesize, >={Stealth[length=5pt]},
          d/.style={draw=coolgray, rounded corners=2pt, fill=boxgray,
                    minimum width=1.7cm, minimum height=3.0cm, align=center}]
        \node[d, draw=cardinalred] (c) at (0,0) {XIAO};
        \node[d] (t) at (3.7,0) {microSD\\card};
        \draw[->] (0.85,1.05) -- node[above, font=\scriptsize]{SCK: clock} (2.85,1.05);
        \draw[->] (0.85,0.35) -- node[above, font=\scriptsize]{MOSI: data out} (2.85,0.35);
        \draw[<-] (0.85,-0.35) -- node[above, font=\scriptsize]{MISO: data in} (2.85,-0.35);
        \draw[->] (0.85,-1.05) -- node[above, font=\scriptsize]{CS: select} (2.85,-1.05);
      \end{tikzpicture}
    \end{column}
    \begin{column}{0.48\textwidth}
      \small
      \begin{itemize}
        \item One clock wire and one data wire for each direction.
        \item No address. Each device has its own select wire (CS).
        \item Data goes in the two directions at the same time.
        \item The speed is megabits each second.
        \item Cost: one more pin for each device.
      \end{itemize}
    \end{column}
  \end{columns}
  \vskip 0.6em
  \keypoint{I2C saves pins. SPI gives speed. A sensor with a low data rate
    usually has I2C. A memory card or a fast display has SPI.}
\end{frame}

% ------------------------------------------------------------------------- I2S
\begin{frame}{I2S, PDM, and the camera bus}
  \begin{columns}[T]
    \begin{column}{0.47\textwidth}
      \begin{block}{Audio: I2S and PDM}
        \begin{itemize}
          \item I2S sends audio samples at an exact rate. It has clock
                wires and one data wire.
          \item The microphone of the kit uses PDM: a stream of single
                bits at a high rate.
          \item A filter in the ESP32-S3 makes samples of 16 bits.
          \item Pins: clock GPIO42, data GPIO41.
        \end{itemize}
      \end{block}
    \end{column}
    \begin{column}{0.47\textwidth}
      \begin{block}{Images: a parallel bus}
        \begin{itemize}
          \item The camera sends 8 bits at the same time on 8 data pins.
          \item More signals mark each pixel, each line, and each image.
          \item The bus uses 14 pins. They are on the camera connector
                of the XIAO.
        \end{itemize}
      \end{block}
    \end{column}
  \end{columns}
  \vskip 0.3em
  \keypoint{The hardware clocks the audio and the image data. The program
    reads complete buffers. It does not read single samples.}
  \source{Pin numbers: \emph{Machine Learning Systems}, XIAOML Kit,
    ``Setup''.}
\end{frame}

  \vskip 0.2em
  \small
  \begin{itemize}

\begin{frame}[fragile]{Interrupts: react to an event}
  \begingroup\centering
  \begin{tikzpicture}[font=\scriptsize, x=0.9cm, y=1cm, >={Stealth[length=5pt]}]
    \node[anchor=east] at (-0.1,0.3) {main program};
    \node[anchor=east] at (-0.1,-0.5) {handler};
    \fill[coolgray!35] (0,0.1) rectangle (3.6,0.5);
    \fill[cardinalred!55] (3.6,-0.7) rectangle (4.5,-0.3);
    \fill[coolgray!35] (4.5,0.1) rectangle (8.6,0.5);
    \draw[->] (3.6,1.1) node[above] {event: the pin goes low} -- (3.6,0.55);
    \draw[->, coolgray] (3.6,0.1) -- (3.6,-0.25);
    \draw[->, coolgray] (4.5,-0.3) -- (4.5,0.05);
    \draw[->, coolgray] (0,-1.0) -- (8.8,-1.0) node[right] {time};
  \end{tikzpicture}\par\endgroup
  \begin{columns}[T]
    \begin{column}{0.47\textwidth}
      \small
      \begin{itemize}
        \item Polling: the program reads the pin again and again. It can
              miss a short event.
        \item Interrupt: the hardware stops the main program and starts
              a handler function.
        \item Keep the handler short. Set a flag. Do the work in the main
              program.
      \end{itemize}
    \end{column}
    \begin{column}{0.50\textwidth}
\begin{lstlisting}[style=python]
from machine import Pin
pressed = False

def on_press(pin):
    global pressed
    pressed = True   # set a flag only

button = Pin(0, Pin.IN, Pin.PULL_UP)
button.irq(trigger=Pin.IRQ_FALLING,
           handler=on_press)
\end{lstlisting}
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{Timers: a constant sampling rate}
  \begingroup\centering
  \begin{tikzpicture}[font=\scriptsize, x=0.078cm, y=1cm]
    % 1 unit = 1 ms. The read needs 4 ms in this example.
    \foreach \t in {0,20,...,120} {
      \draw[coolgray!60, dashed] (\t,-0.3) -- (\t,1.9);
      \node[below, coolgray] at (\t,-0.3) {\t};
    }
    \node[anchor=west, font=\footnotesize, inner sep=1pt] at (0,2.3)
      {\textbf{Read, then wait 20 ms:} the period is 24 ms};
    \foreach \k in {0,...,4} {
      \fill[cardinalred!55] (\k*24,1.3) rectangle (\k*24+4,1.8);
    }
    \node[anchor=west, font=\footnotesize, fill=white, inner sep=1pt]
      at (0,0.78) {\textbf{Wait for the next deadline:} the period is 20 ms};
    \foreach \k in {0,...,5} {
      \fill[treegreen!60] (\k*20,-0.1) rectangle (\k*20+4,0.4);
    }
    \draw[->, coolgray] (0,-0.3) -- (126,-0.3) node[right] {ms};
  \end{tikzpicture}\par\endgroup
  \vskip 0.3em
  \small
  \begin{itemize}
    \item The target is 50 Hz: one sample each 20 ms.
    \item A fixed wait after each read adds the read time to each period.
          With a read time of 4 ms, the rate is 41.7 Hz, not 50 Hz.
    \item A timer gives deadlines at 0, 20, 40 ms. The program waits for
          the next deadline. The read time does not change the rate.
  \end{itemize}
  \keypoint{The model of Day 3 expects 50 Hz. Data at a different rate is
    a different signal. Measure the rate in the lab.}
  \source{The read time of 4 ms is an example, not a measured value.}
\end{frame}

  An extract from the data sheet of a different TinyML board:
  \vskip 0.3em

  \begin{tabular}{@{}L{0.20\textwidth}L{0.72\textwidth}@{}}
    \toprule

    Microphone      & MP34DT06JTR, PDM output \\
    Pressure        & LPS22HB, I2C \\

    \bottomrule
  \end{tabular}}
  \vskip 0.3em
  \begin{enumerate}
    \item How much flash and how much RAM does the board have?
    \item Which bus does each sensor use?
    \item Four sensors use the same two wires. How does the
          microcontroller select one of them?
    \item A model has 300 KB of weights and a tensor arena of 100 KB. The
          program needs 300 KB of flash. Does the model fit? Which number

  \end{enumerate}
  Work with your neighbour for 5 minutes.
  \sourcehere{Data sheet of the Arduino Nano 33 BLE Sense Rev2
    (ABX00069).}
}

\answerframe{read a data sheet extract}{%
  \begin{enumerate}
    \item 1 MB of flash and 256 KB of RAM. The board has no PSRAM.
    \item The IMU, the pressure sensor, the temperature and humidity
          sensor, and the light sensor use I2C. The microphone uses PDM,
          which the microcontroller reads with its audio interface.
    \item Each I2C device has its own address. The controller sends the
          address at the start of a transfer. Only that device answers.
    \item \textbf{Flash:} $300 + 300 = 600$ KB. This is less than 1 MB, so
          the weights fit.\\
          \textbf{RAM:} the arena needs 100 KB of the 256 KB. You also
          need the RAM that the program uses for its own data. The model
          fits if the program uses less than 156 KB.
  \end{enumerate}
  \vskip 0.3em
  The same four questions apply to each new board: the flash, the RAM, the
  sensors, and the bus of each sensor.
}
